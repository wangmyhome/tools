### 2a.1 CodexNotch 插件调研结论（`~/Desktop/Codex监控插件`）

Swift 原生灵动岛应用（`CodexMonitor.swift` 采集 + `StatusPanel`/`NotchSurface` 面板 + `DuckWebView.swift` 驱动网页鸭）。关键事实：

- `build.sh` 直接 `cp fluffy-duck/app.html` 打包——插件与本项目本就联动；它调 `window.yaliya.setMonitor/setTasks/setEvent/showTasks`，**但当前 app.html 并未实现这组接口**，optional call 静默失效。
- 它的采集逻辑与本文档 M0 同源（同一批 SQLite 库），但多了三条我们没做的规则（见下）。

**采纳清单**（进 M1）：

### 2a.2 气泡卡规格

**形态**：独立置顶小窗（复用 bubble.html 机制）。

**头顶药丸岛（2026-11-02 四次定稿，参考 CodexNotch 折叠岛 + 用户截图）**：卡片整体「戴」在小鸭头上，与鸭子融为一体——

- **折叠态（常驻药丸）**：圆角药丸悬在鸭头顶上方（底缘在头顶投影锚点上方 ~12px；2026-11-02 用户两轮反馈压头遮挡，从「戴帽子」上移共 18px），无阴影，内容 = 状态图标（19px 大圆点，参考 CodexNotch：绿底白勾/五彩转圈）+ 状态词（13px 粗体）+ 细 chevron（CSS 边框箭头，展开翻转）。药丸**常驻**跟随鸭子移动（渲染层每帧投影头顶点上报），监控关闭时药丸消失（鸭子回归纯宠物）。
  - 状态图标：空闲=**空心圆环**（12px + 2px 灰白描边，2026-11-02 定稿：原绿勾太抢眼，要的是安静）；**运行中=五彩发光旋转圆圈**（conic-gradient 彩环 1s/圈 + 辉光）；失败/卡住等=对应语义色圆点。
  - 状态词：空闲/完成/失败/卡住/过劳/被卡/打盹；**运行中改为「N 个任务执行中」**（N=活动任务数，2026-11-02 定稿，对齐 CodexNotch 文案）。
  - 显示时机（pillMode 托盘可切）：`always` 一直显示（默认）；`active` 只在运行时显示。
- **展开态（最近任务列表，点击展开）**：点击药丸/箭头即展开；任务列表从药丸**向上**长出（与药丸连体，间距 5px），布局与 CodexNotch 展开视图一致：药丸即表头（箭头翻转朝上 ∧），下方「最近任务」节 + 任务行列表（状态图标 | 项目·标题一行截断 | 目录等宽小字 | 右侧状态词+等宽耗时），最多 8 行。**再次点击 → 收回药丸形态**；无任何自动收（不悬停误触、不自动收回）。
- **旧交互废除清单（四次定稿）**：hover 鸭子本体 ≥180ms 自动弹卡 / 移开 500ms 收回 / 完成失败事件自动弹卡 3s / 一任务一卡 + n/m 角标 + 4s 轮播 + 层叠边——全部移除；**v0.4 最终定案连悬停药丸自动展开也不做**（曾短暂引入又撤销），展开/收回只靠点击。
- **贴顶翻面（v0.4.1，用户拍板 A+B）**：展开高（渲染层离屏量测上报）> 头锚上方可用空间 → 翻面：`#island` 切 column-reverse，列表从药丸**向下**长出盖住鸭子身体，chevron 镜像翻转；翻完下方仍放不下 → 主进程下发 `maxH`，`#panel` 限高 + 卡内滚动。**方向在展开瞬间锁定**（阈值线附近拖鸭子不抽搐），收起后下次展开重算。药丸带 `[头锚-12-药丸高, 头锚-12]` 在向上/向下两形态下完全一致——切换形态药丸永不跳。鸭子让位（主动挪开避让）讨论后弃用——展开瞬间鸭子被盖住，收起即归。
- **可点击（2026-11-02 九次定稿：默认穿透 + 命中轮询，固定窗高架构）**：并行重构后卡窗改为**固定 328×N 窗高**（展开/收起只动 CSS grid，不改窗高）+ **默认穿透**（`setIgnoreMouseEvents(true,{forward:true})`），主进程 20ms 轮询 `screen.getCursorScreenPoint()`：光标落在药丸 ±12px 或展开面板区 → 吃鼠标，否则穿透（透明区让位给拖鸭子）。
  - **命中区 y 必须按布局约定推算，不能信上报 y（实测根因，2026-11-02）**：药丸被 CSS 钉在窗底（常规）/窗顶+8（翻面），窗内 y 随窗高联动。首帧量测发生在窗口 48px→200px 的生长过渡期，上报 y=14；窗口长高后药丸移到 y=166，但渲染层签名去重不再重报 → 主进程命中区永久错位 152px → 光标点在可见药丸上、轮询判定 miss、窗口保持穿透 → **点药丸没反应**。修复：`pillScreenRect` 的 y 一律 `翻面? 窗顶+8 : 窗底-药丸高` 推算，x/宽才用上报值；渲染层加 `resize` 监听强制重报兜底。
  - **验证陷阱**：主进程轮询跟随**真实光标**——用户正在用电脑时，swift 合成鼠标会被瞬间覆盖、点击落在轮询盲区，所有合成点击测试无效。验证命中要么让用户亲手点，要么读 card-debug.log 的 `expand req` 是否随真实点击出现。
  - 窗口 `focusable:false` 不抢焦点不变；card 事件写 `~/Library/Application Support/鸭力鸭/card-debug.log`（200KB 滚动）供排查。
- **位置自适应**：以头顶投影点为锚（不再是窗口几何中心），横向越界夹回工作区；顶部贴边时药丸与头脱开上夹，不翻面（翻面会遮脸，弃用）。
- **抗抖动 + 去刷新感（2026-11-02 五次定稿，用户反馈「移动到鸭子/药丸上有抖动、像按钮被刷新」）**：
  - **锚点冻结**：光标在卡窗上（±4px）或展开期间，`placeCard` 不更新 `cardAnchorLock`——鸭子呼吸/视差导致的头顶点微动不再传导给药丸；
  - **无变化不重排**：`setBounds` 前比对四元组，位置尺寸没变就 return——backdrop-blur 玻璃随窗口重合成会闪一下（用户描述的「按钮刷新感」主因）；
  - **渲染层签名跳过**：`renderPill` 对图标/状态词做签名比对，状态没变不重建 DOM——五彩转圈的 1s 旋转动画不再被 5s 快照打断重放；
  - **按压变色移除**：删 `#pill:active` 深色反馈（用户不要按钮感，「只有箭头上下掉头就可以了」）。
  - **箭头 v2（中心翻转）**：两条臂 `::before/::after` 共享元素中心为顶点（top/left 50% + 相对中心的旋转），展开/收起绕顶点 `rotate(0↔180deg)` 原地掉头——旧 border 盒角版翻转时顶点会斜着划走。
- **点击零闪烁 + 拖动跟随（2026-11-02 七次定稿）**：
  - **弹出动画删除**：`#panel` 的 rise 缩放淡入读起来像「点击刷新」，用户只要箭头掉头这一处动效——面板直接出现/消失；
- **点击零抖动（2026-11-02 八次定稿：等药丸变形）**：用户三轮反馈点击展开/收起仍有「抖动/刷新感」。根因不止同帧双重排——`placeCard(true)` 锚点重算本身带微位移，且窗宽变化触发药丸横向重居中。定案：
  - **药丸带基准**：主进程维护 `cardPillBand = {bottom, cx}`（药丸底缘/中心的屏幕坐标），placeCard 每次落位时刷新；
  - **等药丸变形**：展开/收起/量测上报全部只走 `resizeCardKeepingPill(W,H)` 一次 setBounds——以药丸带反推窗口矩形（常规态窗口底贴药丸带底；翻面态窗口顶钉在带顶上方 8px），药丸在变形前后一个像素不挪，玻璃不重采样；
  - **展开不再 placeCard(true)**：翻向判定改用冻结锚点（= 药丸实际位置），重算锚点的微位移就是点击抖动；没有量测值时跳过预变形，由 card:size 等药丸路径兜底（同样只动一次）；
  - **量测必须用真数据（本轮实测抓到的元凶）**：`expandedHeight()` 量测前必须先 `renderRows()`——面板 DOM 停留在旧内容（空列表量出 79px）会让主进程以为上方放得下而不翻面 → 贴顶展开窗口被工作区钳位 → 药丸下坠 75px 盖住鸭脸（用户看到的「点击抖动」就是它）；
  - **药丸高实测值**：`#pill` 实际渲染 34px（32 内容 + 上下 border），主进程 `PILL_H=32` 常量差 2px——card:size 上报的 `pill.h` 覆盖 `cardPillH`，翻面/变形公式统一用它（残留 ~0.4px 亚像素差为面板内容排版小数，不可见）；
  - 弹出动画（rise）保持删除态——面板直接出现/消失，唯一动效是箭头掉头。
  - **拖动跟随**：`win:move`（拖鸭子）后 300ms 内 placeCard 解冻锚点——展开态拖鸭子卡片跟着走（用户反馈），停手后重新冻结；
  - **收起校正**：collapseCard 把锚点锁快照校正回当前头顶——展开期间鸭子被拖走过的话，收起时药丸落回鸭头顶而不是弹回展开时的旧位置。
- **联动**：聊天气泡上移避让药丸高度（不再压住头顶岛）；老板键 / 隐藏小鸭时药丸随鸭一起消失。

## 3. 数据层：读什么、怎么读、多快

### 3.1 四个库各管什么

| 库 | 表 | 用途 | 轮询频率 |
| --- | --- | --- | --- |
| `thread_history_1.sqlite` | `thread_turns` | **权威回合事实**：状态、起止、耗时、错误 | 1s（热） |
| | `thread_items` | 进度细节：命令数、文件数、是否在动 | 1.5s（热） |
| `state_5.sqlite` | `threads` | 标题、工作区、git 分支、token、归档 | 30s（冷） |
| | `thread_read_receipts` | 未读标记（完成但没看过的线程） | 30s（冷） |
| `goals_1.sqlite` | `thread_goals` | 目标受限：`usage_limited / budget_limited / blocked` | 10s |
| `logs_2.sqlite` | `logs` | **事件流加速器**：`turn/started`、`turn/completed`、`thread/status/changed`、`error` | 1s（水位线） |

### 3.2 取数方式（关键决策）

Electron 33 内置 Node 20，没有 `node:sqlite`。三条路：

| 方案 | 成本 | 现状 |
| --- | --- | --- |
| **`sqlite3` CLI + `-readonly -json`** | 零依赖，一次调用可 `ATTACH` 跨库 join，实测 < 10ms | ✅ **M0 采用** |
| `better-sqlite3` | 原生模块，需 `electron-rebuild`，打包链路要改 | 推迟到需要 < 200ms 延迟时 |
| 升级 Electron 到 37+（Node 22.16+ 有 `node:sqlite`） | 有，但 `main.js` 里那套透明窗/全屏可见/空间归属的配方很脆，升级要重测全部窗口行为 | **不做**，风险收益不划算 |

CLI 单次调用模板（一次拿全，别开多个进程）：

```sql
ATTACH DATABASE '~/.codex/state_5.sqlite' AS st;
ATTACH DATABASE '~/.codex/goals_1.sqlite' AS g;
SELECT t.thread_id, t.status, t.started_at, t.completed_at, t.duration_ms,
       th.title, th.cwd, th.git_branch, th.archived,
       g.status AS goal_status
FROM thread_turns t
LEFT JOIN st.threads th ON th.id = t.thread_id
LEFT JOIN g.thread_goals g ON g.thread_id = t.thread_id
WHERE t.status = 'inProgress'
   OR COALESCE(t.completed_at, t.started_at) > strftime('%s','now') - 86400;
```

**提速技巧**：`-wal` 文件变化即触发一次立即刷新（`fs.watch` 盯 `thread_history_1.sqlite-wal`），平时 1s 兜底轮询。事件到达延迟可从 1000ms 压到 ~150ms，且几乎不耗 CPU。

### 3.3 僵尸回合：必须有的判定规则

实测 5 条 `inProgress` 全是从未收尾的僵尸（8~9 月启动，`completed_at` 为 NULL）。**不能信 `status='inProgress'` 这个字段本身**。

判定为「真的在跑」必须同时满足：

1. `status = 'inProgress'`，且
2. 该线程最后一条 item 的 `created_at_ms` 距今 **< 90s**，且
3. 该线程在 `logs` 里有对应事件活动（可选加分项）

否则标记为 **「疑似中断」**：鸭子不演奔跑，岛里用灰色 `‖` 显示，菜单提供「标记为已结束」（只写本地忽略名单，不改 Codex 数据库）。

### 3.4 待授权：老实说它拿不到

全库没有 approval 落盘，日志里 `requestApproval` 出现 0 次。所以：

- **M0 / M1（只读阶段）**：不谎称「待授权」。能给的只有弱信号——`inProgress` 且 **90s 无任何新 item** 且最后一条 item 是 `commandExecution` → 岛里显示「**可能卡在等你**」，灰色问号图标，措辞必须留余量。
- **M2**：走 `ipc.sock`（`codex app-server proxy`）拿真正的 `item/*/requestApproval` / `serverRequest/resolved`，此时才敢用红色 🔴 和「要你点头」。

这条边界要写进 UI 文案，不能只留文档里。

## 4. 鸭子演什么：状态映射

映射表是唯一权威，实现时集中在一处常量里。

| Codex 事实（数据源） | 鸭子状态 | 岛 | 托盘 | 钉住 |
| --- | --- | --- | --- | --- |
| 1 条活动回合 | `run` 奔跑 | 折叠态显示项目名 + 耗时 | 🟢 | 否 |
| ≥2 条活动回合 | `sprint` 冲刺 | 折叠态显示「2 个在跑」 | 🟢×N | 否 |
| 回合 `failed` / `error` 事件 | `cry` 哭泣 | 红条 + 失败原因首行 | 🔴 | 60s |
| `turn/completed` | `celebrate` 庆祝 | 绿色 ✓ 闪一下即收 | 🔵 未读保持 | 否，9s 自回 |
| 回合 `interrupted` | `overload` 躺平（被打断，歇一下） | 灰条 | ⚪ | 否，15s 自回 |
| 单回合 > 20min 仍在跑 | `overload` 躺平（过劳） | 橙条「跑了 20 分钟」 | 🟠 | 否 |
| `thread_goals.status ∈ usage_limited / budget_limited` | `overload` 躺平 | 橙条「额度用完了」 | 🟠 | 直到目标态变 |
| `thread_goals.status = blocked` | `playdead` 装死 | 橙条「被卡住了」 | 🟠 | 直到目标态变 |
| ~~待授权~~（M2 才有真信号） | `angry` 生气 | 红条 + 批准/拒绝 | 🔴 | 是 |
| 疑似卡住等你（弱信号，见 3.4） | `angry`（半强度：不跺脚只瞪眼） | 灰问号「可能卡在等你」 | 🟠 | 是，直到有活动 |
| ~~待回答~~（M2 才有真信号） | `playdead` 装死 | 橙条 + 打开 | 🟠 | 是 |
| 无活动 ≥ 5min | `bath` 泡澡 | 收起 | 🐤 | 否 |
| 无活动 ≥ 30min | `sleep` 打盹 | 按「空闲时是否显示」处理 | 🐤 | 否 |
| 数据源读不到 / 过期 > 5min | `sleep` + 岛挂「状态可能过期」 | 💤 | 是 |
| 老板键 `Ctrl+Option+B` | `boss` 装正经 | 全部收起 | 🤫 | 30s 后自动恢复（沿用现有玩法计时） |

现成动画的巧合复用：`playdead` 本来就是「戳一下会醒」、`celebrate` 自带 9s 回收、`overload` 本来就是过劳——这三个映射零成本。

**顺手把前稿的一处语义错误修正掉**：早期 Swift 版把「跑满 10 分钟」映射到 `boss`（装正经），语义是错的——`boss` 必须只留给老板键这个人工态，否则用户按了老板键分不清是不是监控在演。过劳一律用 `overload`。

## 5. 岛面规格（~~本次设计的重点~~ v0.3 起由第 2a 节气泡卡取代，本节存档）

### 5.1 三档形态

| 档位 | 尺寸 | 触发 | 内容 |
| --- | --- | --- | --- |
| **折叠** | 高 28，宽 96–240（按内容自适应） | 常驻（受「空闲时显示」开关控制） | 状态色点 · 计数 · 最高优先级动作图标 · 最长耗时 |
| **Peek** | 高 72，宽 320 | 鼠标悬停 180ms，或新事件到达后自动展开 3s | 项目名 · 状态词 · 摘要一行 · 主按钮 |
| **全展** | 高 ≤ 380，宽 360 | 点击岛 / 点击鸭子 / 快捷键 / 点通知 | 线程列表（最多 6 条）+ 底部「打开 Codex」「设置」 |

动画：从屏幕顶缘**下探**（`translateY` 0.28s 弹性 `cubic-bezier(.32,1.4,.6,1)`），收起时**上收** 0.2s。岛始终贴顶居中（刘海机型与刘海同高、不遮挡），可设置「跟随鼠标所在屏」或「仅主屏」。

### 5.2 岛里放什么（严格信息边界）

每条线程一行，最多三行文字：

```
● fluffy-duck        跑 3:42
  pytest 通过 12 个用例          ← 摘要行（隐私档位控制）
  [ 打开 ]  [ 静音 ]
```

- 第一行：状态点 + **项目目录名**（不是完整路径）+ 状态词 + 耗时
- 第二行：摘要行，按隐私档位取「命令名」或「变更文件数」或「仅线程名」
- 第三行：动作按钮

**永不显示**：对话正文、补丁内容、token 明细、完整路径、`item_json` 原文。

### 5.3 动作按钮的可用性分级

| 阶段 | 待办类卡片上的按钮 |
| --- | --- |
| M0 | 只有 `[ 打开 Codex ]`（跳转） |
| M1 | `[ 打开 Codex ]` `[ 静音这条 ]` |
| M2 | `[ 批准 ]` `[ 拒绝 ]` `[ 打开 Codex ]` —— 需二次确认 + 本地审计日志 |

**M0/M1 阶段一个写操作都不许有**，这是安全底线。

### 5.4 与鸭子的联动

- 点鸭子 → 岛展开到全展（Qoder 同构：点桌宠呼出面板；你现有 Swift 版也是这么做的 `showTasks(true)`）
- 岛展开时鸭子**不改变姿态**（不抢戏）
- 拖拽/摸头/抱飞时岛**不自动展开**（手感优先，见第 7 节）

## 6. 完整交互脚本（用户视角走一遍）

1. **我在 Codex 里发一句话** → 1~2s 内鸭子开始奔跑，岛折叠态出现「fluffy-duck 跑 0:01」。
2. **跑的过程中** → 岛折叠态耗时每秒跳动；鸭子偶尔甩头；多开一个线程时鸭子变冲刺、岛显示「2 个在跑」。
3. **跑完** → 鸭子撒花 9s；岛绿色 ✓ 闪一下；如果我没在 Codex 窗口前，来一条系统通知「这一轮跑完了，去看一眼」；点通知 → 岛展开到那条线程。
4. **失败了** → 鸭子哭 60s；岛红条显示错误首行；托盘变红；发通知。
5. **我离开电脑 5 分钟** → 没任务：鸭子泡澡；有任务在跑：鸭子继续跑，岛照常。**不会因为我不在就假装一切正常**。
6. **数据断了**（Codex 没开 / 库读不到）→ 鸭子打盹，岛挂「💤 状态可能过期」，托盘 💤。绝不显示「一切空闲」。
7. **我不想看这些** → 老板键，鸭子装正经、岛收起、通知静默；再按一次恢复。

## 7. 仲裁：谁说了算

### 7.1 优先级（高 → 低）

```
待授权(M2) > 待回答(M2) > 疑似卡住 > 目标受限/过劳 > 异常 > 完成庆祝
> 运行中（sprint > run）> 玩法互动（摸头/戳戳/抱飞/喂食）> 泡澡/打盹 > 低电量无精打采
```

### 7.2 三条规则

1. **手感优先 10 秒**：用户正在摸头/拖拽/抱飞/喂食时，除「待授权/待回答」外，监控不得覆盖玩法演出；10s 无输入后同步真实状态。时长可配（5/10/30s）。
2. **钉住状态**：待办类没有自回空闲计时，只有事实消失才解除。状态层要新增 `pinned` 标记——现有一律「庆祝 9s / 生气 6.5s 自回空闲」是不够的。
3. **多任务只演一个结论**：鸭子只演最高优先级那一个；数量交给岛和托盘的角标。

### 7.3 需要改的现有代码（结构性）

| 现状 | 要改成 |
| --- | --- |
| `state` 是单值字符串，`setState()` 无参数 | `setState(next, { source, priority, pinned, ttl })`，渲染层持有一个 `monitor` 槽和一个 `game` 槽，按优先级合成 |
| `state:announce` 只回报字符串 | 回报 `{ state, source, pinned }`，主进程据此刷托盘 |
| `writeCfg` 是浅合并 `{...readCfg(), ...obj}` | 改按键深合并，否则 `codex` 配置段整段回写会互相覆盖 |
| 无 `Notification` | 引入，并处理 macOS 授权失败（失败时菜单显示「未授权，点这里去系统设置」） |

## 10. 风险与未验证项

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | `logs_2.sqlite` 是诊断日志，可能轮转/被清理 | 事件流加速失效 | 只当加速器，**事实永远以 `thread_turns` 为准**；查不到就退回 1s 轮询 |
| 2 | `outgoing_message` 事件的 `thread_id` 列为 NULL | 事件无法直接归属线程 | 靠时间窗 + `turn` 表回查，不依赖它做归属 |
| 3 | 待授权无落盘（已实测） | M0/M1 只能弱提示 | 措辞留余量，不谎称；M2 才敢用红点 |
| 4 | 僵尸 inProgress（实测 5 条） | 会假装一直在跑 | 90s 无活动 + 手动「标记已结束」 |
| 5 | 升级 Electron 会破坏窗口配方 | 全屏可见/空间归属可能失效 | **不升级**，走 `sqlite3` CLI |
| 6 | `ipc.sock` 归 ChatGPT.app 独占，多客户端并发未验证 | M2 的批准能力可能做不了 | 先做一次 `proxy` 并发验证再排期 |
| 7 | `threads.title` 可能包含用户原话 | 隐私泄露到气泡/通知 | 默认「仅显示目录名」，标题需用户显式开启 |
| 8 | 高频事件（delta）刷屏 | 鸭子变噪音源 | 250ms 聚合窗口；`*Delta` 类事件一律丢弃不入状态机 |

## 11. 附：30 秒自检脚本

验证数据源还活着（不写任何东西）：

```bash
sqlite3 -readonly -json ~/.codex/thread_history_1.sqlite \
  "ATTACH DATABASE '$HOME/.codex/state_5.sqlite' AS st;
   SELECT t.thread_id, t.status, t.duration_ms, th.title
   FROM thread_turns t LEFT JOIN st.threads th ON th.id=t.thread_id
   ORDER BY COALESCE(t.completed_at,t.started_at,0) DESC LIMIT 5;"
```

看到最近 5 分钟的回合 = 数据源正常；报错或最新一条停在几天前 = 需要降级到「状态可能过期」。
